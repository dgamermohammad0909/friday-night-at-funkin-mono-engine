--- XBOX PORT ARCHITECTURE ---

The Xbox port is a UWP (Universal Windows Platform) app that reuses all the game's
source code from the main desktop project, with these Xbox-specific replacements:

FILES IN Xbox/ FOLDER:
  - FNF_Xbox.csproj         → UWP project file, links source from parent via <Compile Include="..\" Link="">
  - XboxGame.cs             → Replaces FNFGame.cs. Same API but uses RenderTarget2D for resolution scaling
                               (renders at 1280x720, scales to 1920x1080 with letterboxing)
  - XboxAudioManager.cs     → Replaces AudioManager.cs. Uses NVorbis (pure managed OGG decoder)
                               instead of NAudio (Win32-only). Streams OGG via DynamicSoundEffectInstance.
  - App.xaml / App.xaml.cs   → UWP entry point. Sets up GamePage, handles PLM (Process Lifetime Management)
  - GamePage.xaml/.cs        → Hosts MonoGame SwapChainPanel, initializes via XamlGame<XboxGame>.Create()
  - LoadingScene.cs          → First scene on Xbox. Downloads content from GitHub if needed, then initializes
                               managers across multiple frames to avoid Xbox startup timeout.
  - ContentDownloader.cs     → Downloads content.zip from GitHub Releases on first launch. Extracts to
                               LocalState/Content/. Versioned so content only re-downloads when bumped.
                               URL: https://github.com/dgamermohammad0909/friday-night-at-funkin-mono-engine/releases/download/content-v1/content.zip
  - UwpPolyfills.cs          → Adds Index/Range structs for C# 8 range syntax (x[..2], x[1..]) which
                               is missing on UWP's .NET Native/.NET Standard 2.0 runtime.
  - GlobalUsings.cs          → Global usings + type alias: "global using FNFGame = FNF_MonoGame.XboxGame;"
                               so all scenes that reference FNFGame.SCREEN_WIDTH etc. work unchanged.
  - Package.appxmanifest     → UWP manifest (app identity, capabilities, logos)
  - Properties/Default.rd.xml → .NET Native runtime directives

BUILD SCRIPTS:
  - build_xbox.ps1           → Full build pipeline: checks prereqs (Windows SDK, MSBuild) → NuGet restore
                               → MSBuild compile → creates APPX package → optional deploy to Xbox via IP
                               Usage: .\build_xbox.ps1 -Release -Deploy -XboxIP 192.168.1.xxx
  - install_prerequisites.ps1 → Installs UWP workload + Xbox dev tools via VS Installer
  - package_content.ps1      → Zips Content/ folder for GitHub Release upload
  - upload_content_to_xbox.ps1 → Uploads Content/ to Xbox's LocalState via Dev Portal REST API
  - browse_xbox_files.ps1    → Browse files on Xbox via Dev Portal

--- HOW THE XBOX PORT WORKS ---

1. CODE SHARING: Xbox project links ALL .cs files from parent (Engine/, Gameplay/, Scenes/)
   EXCEPT FNFGame.cs (replaced by XboxGame.cs), Program.cs (UWP has own entry), and
   AudioManager.cs (replaced by XboxAudioManager.cs using NVorbis instead of NAudio).

2. AUDIO: Desktop uses NAudio (Win32 APIs) for OGG playback. UWP/Xbox doesn't have Win32.
   XboxAudioManager uses NVorbis (pure managed .NET OGG decoder) to decode OGG streams,
   converts float samples to PCM bytes, and feeds them to DynamicSoundEffectInstance.
   Supports: music streaming (with looping), player/opponent voice tracks, sound effects
   (cached as SoundEffect), music fade-out, pause/resume, intro→loop chaining.

3. CONTENT: NOT bundled in the APPX (keeps package small ~4MB for instant Xbox startup).
   Instead, ContentDownloader.cs downloads a content.zip from GitHub Releases on first launch.
   Extracted to LocalState/Content/. Alternative: upload via Dev Portal REST API.

4. RENDERING: XboxGame renders to a 1280x720 RenderTarget2D, then scales to the back buffer
   (1920x1080) with correct aspect ratio letterboxing. This matches the desktop resolution.

5. CONDITIONAL COMPILATION: #if XBOX_UWP for platform-specific code.
   The Xbox project defines XBOX_UWP, NETFX_CORE, and WINDOWS_UAP symbols.

6. CONTROLLER: InputManager handles both keyboard and gamepad. Xbox controller mapping:
   - DPad/Left Stick = Navigate menus
   - A/Start = Confirm, B/Back = Back
   - Gameplay: DPad + face buttons (A/B/X/Y) + triggers for note lanes
   - Face buttons auto-switch between note input (gameplay) and menu nav (menus)

--- DEPLOYMENT OPTIONS ---

Option A: Command line → .\build_xbox.ps1 -Deploy -XboxIP 192.168.1.xxx
Option B: Visual Studio → Open FNF_Xbox.csproj, set x64, Remote Machine target, F5
Option C: Xbox Device Portal → Browser to https://XBOX_IP:11443, upload APPX manually
Content upload: Dev Portal File Explorer → LocalState/Content/, or use upload_content_to_xbox.ps1
