PROBLEM
================================================================================
Character select scene FREEZES (Windows "Not Responding") on load
Freeplay scene works fine with DJ animations
User confirmed: "Character select is NOT responsive / STILL FREEZES"

================================================================================
ROOT CAUSE IDENTIFIED
================================================================================
Creating 100+ RenderTarget2D allocations + rendering to each is TOO SLOW
- Each RenderTarget2D: allocate GPU memory → set as target → clear → render → unset
- Character select loads 4 sheets (2 chars × player+spectator) synchronously
- Each sheet's preRenderComposites generates 20-65+ composite frames
- Total: hundreds of RT allocations blocking main UI thread > 5 seconds

Previous fix (RT retention) was necessary but NOT sufficient
- Removed GetData/SetData GPU readback but freeze persists
- Still creating too many RenderTarget2Ds

================================================================================
FIX APPLIED (THIS SESSION)
================================================================================
Removed preRenderComposites from character select player/spectator loads

File: FNF_MonoGame_Full/Scenes/CharacterSelectScene.cs
Lines 102-103: Changed from
  SpriteSheet.Load(Game, b + "/" + cn + "/player", preRenderComposites: true, preRenderFilter: new[] { "Idle", "Confirm" })
To:
  SpriteSheet.Load(Game, b + "/" + cn + "/player")

Lines 114-115: Changed from
  SpriteSheet.Load(Game, b + "/" + cn + "/spectator", preRenderComposites: true, preRenderFilter: new[] { "IdleLeft", "IdleRight", "Idle" })
To:
  SpriteSheet.Load(Game, b + "/" + cn + "/spectator")

Why this works:
- DrawComposite() already has fallback to DrawSparrow for non-composite sheets
- Character select animations are mostly static idle poses (don't need heavy compositing)
- Saves hundreds of RenderTarget2D allocations
- Stage backgrounds (crowd, speakers, bar) already work without preRenderComposites
- Freeplay DJ still uses preRenderComposites with preRenderFilter (needed for smoothness)
